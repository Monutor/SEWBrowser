# Разделённое окно вкладок (split view) — спецификация

Дата: 2026-09-27 · План: `docs/superpowers/plans/2026-09-27-split-view.md`

## 1. Цель

Разделить окно на две равные панели: одна вкладка занимает левую половину, вторая — правую.
Мотивация — рядом держать «Задания» и карточку задания, или список товаров и карточку, без
семи переключений между вкладками.

## 2. Зафиксированные требования

- **R1.** Разделение доступно только когда открыто **ровно две** вкладки. Иначе пункт меню не показывается.
- **R2.** Разрез вертикальный, панели слева и справа, делят ширину пополам.
- **R3.** Выход из разделения: пункт «Свернуть окно» в ПКМ по вкладке **и** клавиша `Esc`.
- **R4.** Новая вкладка, открытая в разделении (`Ctrl+T`, кнопка «+», переход по ссылке),
  **заменяет** вкладку активной панели; вторая панель не меняется.
- **R5.** Опросная вкладка (первая по порядку, `isPrimary`) **всегда левая** и не зависит от
  разделения: уведомления о заданиях не должны ломаться от перестроения панелей.
- **R6.** Перетаскивание вкладок в разделении отключено (двум вкладкам переставляться нечего).
- **R7.** Всё, что завязано на `activeTab()`/`activeView()` (адресная строка, зум, `Ctrl+F`,
  назад/вперёд, скриншот, печать), в разделении относится к **фокусной панели**.

## 3. Отклонённые альтернативы

- **Подменю со списком вкладок** при >2 вкладок — лишняя сложность ради редкого случая.
- **Перетаскиваемый разделитель** (drag + двойной клик для перестановки панелей) — отдельная
  подсистема с собственными состояниями; вне текущей задачи.
- **Горизонтальный разрез** (сверху/снизу) — реже нужен для работы с двумя документами.
- **Опросная вкладка = активная** — сломала бы `tasks-notify` (хост должен быть один и стабильный).

## 4. Модель (`src/renderer/src/tabs.ts`)

Новое состояние уровня модуля:

```ts
let split: { leftId: number; rightId: number } | null = null
let focusPane: 'left' | 'right' = 'left'
```

Инварианты:

- `split !== null` ⇒ `listTabs().length === 2` и это ровно `leftId`/`rightId`.
- В разделении **порядок массива совпадает с порядком панелей**: `tabs[0]` — левая,
  `tabs[1]` — правая. Отсюда `isPrimary` автоматически у левой (R5).
- `activeTab()` отдаёт вкладку фокусной панели (R7).

Новые экспорты:

| Имя | Сигнатура | Поведение |
|---|---|---|
| `isSplit` | `() => boolean` | признак разделения |
| `canSplit` | `() => boolean` | `listTabs().length === 2 && !split` (для меню) |
| `splitView` | `() => boolean` | разделяет окно; false если нельзя |
| `unsplit` | `() => void` | сворачивает разделение, активна фокусная панель |
| `setSplitFocus` | `(pane: 'left' \| 'right') => void` | перевод фокуса; no-op вне разделения |
| `splitPaneOf` | `(tab: ShellTab) => 'left' \| 'right' \| null` | какая панель у вкладки |

## 5. Поведение

1. **Разделение** (`splitView`): записывает `split = { leftId: tabs[0].id, rightId: tabs[1].id }`,
   `focusPane = 'left'`, применяет раскладку, перерисовывает полосу и панели.
2. **Свертывание** (`unsplit`): `split = null`, активной остаётся вкладка фокусной панели,
   снимается раскладка, `hooks.onActivated(активная)`.
3. **Клик по странице** в панели переводит фокус на неё (только в разделении).
4. **Новая вкладка** в разделении (R4): вкладка активной панели закрывается, новая занимает
   её место в панели и становится активной. Порядок массива сохраняется как `[левая, правая]`.
5. **Закрытие вкладки** в разделении: так как вкладок ровно две, закрытие любой из них
   сворачивает разделение (остаётся одна на всё окно).
6. **Перетаскивание** в разделении заблокировано: обработчики `dragstart` не стартуют (R6).
7. **`Esc`** сворачивает разделение — звеном в существующей цепочке `case 'escape'` после
   панелей, меню адреса и печати.
8. **Перестановка** (вне разделения) не меняет порядок панелей — она в разделение невозможна.

## 6. Раскладка (`styles.css`)

Без новых DOM-узлов. `#tab-views` в разделении — flex-строка; каждой webview задаются
inline-стили `left: 0 | 50%` и `width: 50%`. Разделитель — 1px линия цвета `--border`
на правой границе левой панели (псевдоэлемент или `border-right` на левой webview).

```
вне разделения:  #tab-views > webview { position:absolute; inset:0 }
в разделении:    левая  { left:0;   width:50% }  + правый бордюр
                 правая { left:50%; width:50% }
```

## 7. Меню ПКМ по вкладке

- Вне разделения, вкладок ровно две: **«Разделить окно»** (action `split`).
- В разделении: **«Свернуть окно»** (action `unsplit`).
- В разделении пункты «Закрыть другие» и «Закрыть справа» скрываются (бессмысленны при двух вкладках).

## 8. Границы и отказоустойчивость

- `splitView` при ≠2 вкладках или уже активном разделении — no-op, `false`.
- `setSplitFocus`/`splitPaneOf` вне разделения — no-op / `null`.
- Перестановка (`moveTab`) в разделении запрещена; попытка — no-op.
- Гость уничтожен/вкладка закрыта во время разделения → `unsplit` (остаётся одна вкладка).
- `isPrimary`/`__shellPollHost`/`__tnArmTasksNotify` не трогаются: хост — левая панель.

## 9. Тестирование

`src/renderer/src/tabs.test.ts` (node:test, существующий `FakeEl`):

1. `splitView` при двух вкладках: инварианты, порядок массива, `isPrimary` у левой, фокус.
2. `splitView` при одной/трёх вкладках и повторный вызов — no-op.
3. `unsplit`: разделение снято, активна фокусная панель.
4. `openTab` в разделении заменяет вкладку активной панели, вторая не тронута, порядок сохранён.
5. `closeTab` в разделении сворачивает его.
6. `setSplitFocus` меняет `activeTab()`; вне разделения — no-op.
7. Drag в разделении не стартует (порядок не меняется).
8. Меню: состав пунктов в обоих режимах (через существующий `popupItems`).

Живая проверка (GUI недоступен агенту) — за пользователем: разделить, кликнуть в панель и
убедиться, что адресная строка/печать относятся к ней; третья вкладка заняла активную панель;
`Esc`; уведомления о заданиях продолжают приходить.

## 10. Что НЕ входит

- Перетаскиваемый разделитель и двойной клик для перестановки панелей.
- Горизонтальный разрез, три и более панелей.
- Разделение при >2 вкладках.
- Персистентность вкладок и разделения между запусками.
